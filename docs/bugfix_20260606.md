# Bug Fix: Hermes Bridge 丢失 assistant 回复写入 state.db

日期: 2026-06-06
修改文件: `packages/server/src/services/hermes/agent-bridge/hermes_bridge.py`

## 症状

Session `mq242xqo80xmyp` 中 3 条 user 消息在 state.db 没有对应的 assistant 回复，但 webui.db 完整。

## 根因

`_run_chat` 的 try 块中 `run_conversation()` 在后处理阶段抛异常时（如插件 hook、token 统计等），跳过了其后的 `_sync_result_tail_to_session_db()` 兜底写入。user 消息已通过 `_prepersist_user_message()` 写入 state.db，但 assistant 回复从未写入。

同时，`_sync_result_tail_to_session_db()` 的守卫条件 `after_count > db_count_after_prepersist` 过于宽松——当 `_flush_messages_to_session_db()` 部分写入后异常退出时（写入了一部分但没写全），`after_count` 增大导致守卫跳过，剩余消息丢失。

## 改动方案 A：确保兜底始终执行

**位置**: `_run_chat` 方法（line ~1803）

**前**:
```python
result = session.agent.run_conversation(
    message,
    **kwargs,
)
result = _jsonable(result if isinstance(result, dict) else {"value": result})
self._sync_result_tail_to_session_db(
    session,
    result,
    conversation_history,
    profile,
    db_count_after_prepersist,
)
```

**后**:
```python
result = None
try:
    result = session.agent.run_conversation(
        message,
        **kwargs,
    )
finally:
    result = _jsonable(result if isinstance(result, dict) else {"value": result}) if result is not None else {}
    self._sync_result_tail_to_session_db(
        session,
        result,
        conversation_history,
        profile,
        db_count_after_prepersist,
    )
```

- `run_conversation` 抛异常时 `result` 为 `{}`，`_sync_result_tail_to_session_db` 收到空 dict → `messages` 非 list → 直接 return，安全
- 异常传播不受影响：finally 执行完后原异常继续往外抛，被外层 `except Exception` 捕获

## 改动方案 B：精确计数守卫

**位置**: `_sync_result_tail_to_session_db` 方法（line ~1668）

**前**:
```python
after_count = self._session_db_message_count(session.session_id, profile)
if after_count is None or after_count > db_count_after_prepersist:
    return
```

**后**:
```python
after_count = self._session_db_message_count(session.session_id, profile)
if after_count is None or after_count >= db_count_after_prepersist + len(generated):
    return
```

- `generated` 计算移到守卫之前
- 仅当完整条数已存在时才跳过
- 成功完全写入：`after_count == 预期值` → 跳过 ✅
- 全部未写入：`after_count == prepersist` → 补写 ✅
- 部分写入（极罕见场景）：`after_count < 预期值` → 补写全部，前段可能重复 1 条（不同 id/timestamp）
